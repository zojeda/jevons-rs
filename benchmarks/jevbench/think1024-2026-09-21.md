# JevBench with think=1024 (2026-09-21)

Historical run with the earlier 4,096-token context. See the [thinking rerun with an 8,192-token context](think1024-defaults-2026-09-21.md) and the [current baseline](README.md).

The model answered **184/231 (79.7%)** public cases correctly, compared with **165/231 (71.4%)** at think=0. The same running service attempted all 231 cases with a 1,024-token thought cap.

Among 223 cases with valid responses in both runs, think=1024 got 184 correct and the baseline got 162 correct. Median per-case latency increased 14.9×. The think run's valid-response median was 17.688 s and p95 was 36.182 s; fast rejected requests are excluded from those two figures.

## Settings and limitations

- Same DiffusionGemma 26B-A4B Q4_K_M model, AMD Ryzen AI MAX+ 395 / Radeon 8060S, HIP/native release service, and task order as the baseline.
- think=1024; steps=1, samples=1, sequential=false. One request at a time, no benchmark warmups or retries.
- The 1,024-token value is a maximum. The model may close its thought earlier; usage reports generated thought tokens.
- 5969 output tokens reported across the run; mean 26.8 per valid response; median 4. 5 requests used the full 1,024-token cap.
- The service kept its existing 4,096-token context. It reserves the entire thought budget before inference. Inputs that no longer fit return HTTP 422 and count as incorrect.
- Client timeout increased from 120 seconds to 900 seconds to accommodate thought generation.
- The pinned upstream TypeSafe adapter ignores request_options. The repository wrapper adds only think to the wire body; upstream transport, scoring, and stop rules remain unchanged.
- This run covers the 231 public cases, not the full 534-case leaderboard. Cost remains unknown. Hardware, quantization, and inference settings differ from published reference deployments.

## Request failures

Eight requests returned HTTP 422 because their prompt, thought budget, and canvas required 4,284–4,956 tokens, exceeding the 4,096-token context. The baseline answered three of those eight correctly. Failure details and case IDs are retained in the results snapshot. There were no timeouts or other HTTP failures.
